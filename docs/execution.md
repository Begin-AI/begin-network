# Bounded fixture execution and results

`FixtureWorker` connects independently signed request routing to delegated permission and single-owner unit accounting. It accepts only `calendar-overlap / available-overlap` for explicitly configured `fixture:` resources marked synthetic. There is no arbitrary code, command, file path, URL, tool or real calendar access. Request-supplied text cannot add operations or replace local policy.

Inputs are encrypted to the worker's locally pinned encryption key and their box digest is in the signed request. Permission admits optional signed `routing` and `sealed_digest` metadata alongside the same purpose/action/resource/unit constraints. It does not ignore unknown fields or permit those fields to expand authority. Every fixture operation costs exactly one abstract unit; requesters cannot set a zero cost. Calendar inputs are one to 32 sorted, nonoverlapping minute intervals in a synthetic day. The deterministic operation returns only overlaps with the owner's fixture, with a maximum of 63 fragments.

The worker verifies the request and box binding, verifies/atomically reserves the full grant chain under fresh revocation state, and persists execution state. A completed duplicate returns the same signed token and encrypted box after rechecking current permission; it does not compute or spend again. A failed admitted operation consumes its reservation and records failure. A crash between reservation and completion may leave `pending-or-interrupted`; the worker does not automatically retry it or refund the budget. This conservative at-most-once-attempt design is not exactly-once external effects or guaranteed recovery. No external effects occur in the fixture operation.

The signed result binds the original request digest, exact output ciphertext, status, method/revision provenance and the grant token digests. It is encrypted to a requester encryption key selected from local policy. `receive_result` verifies the worker signature, independently verifies the caller's stored original request under pinned requester keys and its audience against the response signer, and compares the expected grant chain hashes. A different otherwise-trusted worker cannot answer in place of the originally selected worker. It checks result fields, provenance types, ciphertext binding and expiry, then applies durable replay admission before decrypting/validating output.

Receiver admission is also conservative: an admitted response that cannot be decrypted due to wrong local key/configuration cannot be automatically retried using the same replay store. Outcome/recovery protocol work remains. Results retrieved after their expiry are rejected. Revocation stops future worker access/cached retrieval under its policy; it cannot erase an encrypted output already delivered to a requester holding its key.

Provenance is an authenticated worker assertion (`synthetic-calculation`, fixed method, fixture revision), not a proof that an arbitrary remote machine computed honestly, a claim about real human data, or an agent inference. The fixture's expected output is independently checked in the end-to-end demo/tests. A received signature does not itself certify the whole application or P1–E4. See `goal-exchange.md` for the integrated run and `execution-review.md` for adversarial findings/repairs.
